## 不要让所有组件都直接暴露公网

一个稳定的博客通常至少存在三个不同层次：内容构建、静态站点服务与公网入口。

即使网站真正运行在家里的 Ubuntu 上，也建议限制应用端口只在 `127.0.0.1` 监听，然后再由专门的入口统一处理 HTTPS。

## 推荐的分工

| 层次 | 职责 | V1 组件 |
| --- | --- | --- |
| 内容层 | 文章和项目数据 | Markdown + Git |
| 构建层 | 生成最终网页 | Next.js |
| Web 层 | 提供静态文件 | Nginx |
| 公网层 | TLS、访问入口 | Caddy / 合规云入口 |
| 安全层 | 防火墙和补丁 | UFW / 自动更新 |

## 先谈恢复，再谈高可用

一台家庭服务器并不意味着百分之百可用。断电、网络中断与硬盘损坏都可能发生。

最先应该实现的是：构建可重复、容器可重建、重要源文件进入 Git、备份放在另一台设备上，并且能够定期演练恢复。

对于面向中国大陆用户的公开网站，还应提前核实运营商协议、ICP备案和实际接入要求。隧道并不是绕过这些条件的方式。
