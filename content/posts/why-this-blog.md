## 用可验证的方式积累知识

我们每天都会阅读、调试、做实验，真正有价值的却往往不是最后的答案，而是**问题如何被拆解，以及结论怎样被验证**。

这个博客从三个约束出发：

1. **内容属于自己**：所有文章保存在 Markdown 文件中，可用 Git 完整追踪。
2. **部署足够简单**：发布版只有静态文件，不依赖运行时数据库。
3. **阅读体验优先**：不使用侵入式广告、弹窗或繁重的第三方脚本。

## 以 Git 为发布系统

文章从一个普通文件开始：

```markdown
---
title: "文章标题"
date: "2026-10-23"
summary: "写清楚这篇文章解决了什么问题。"
tags: [engineering]
---

这是文章内容。
```

提交后，CI 会验证内容格式并尝试生成静态站点。生产环境可以选择手动部署，也可以在具备安全访问条件后接入自动发布。

## 保留问题、实验与局限

好的技术文章应当明确：目标是什么、约束在哪里、方案为什么成立、还有什么没有被证明。

因此，这里的文章会持续更新，而不是把一次实验写成永久成立的结论。
